Hide data inside
video files.

Encode any file into an H.264 video using a visual grid of gray-level cells. Protected by Reed-Solomon error correction. Survives re-encoding.

Get started View on GitHub
$ ystore encode --input secret.pdf --output video.mp4
$ ystore decode --input video.mp4 --output restored.pdf
# Round-trip verified ✓ 50 KB in 2 frames

Designed for survival

Three layers of protection ensure your data survives video platform re-encoding intact.

Visual Grid Codec

Data is packed into gray-level cells arranged in a grid across each video frame. At 1920×1080: 78×43 = 3,354 cells per frame, each carrying 2 bits.

838 bytes/frame · ~1.3 MB/min

MFSK Audio Channel

Redundant audio track using 64-tone MFSK modulation. Each symbol is a Hann-windowed sine burst decoded via Goertzel's algorithm.

~60 bps · survives AAC

Reed-Solomon ECC

Per-frame error correction automatically matched to grid capacity. ~10% parity shards correct compression artifacts from H.264 at CRF 18.

Auto-matched · survives H.264

How it works

The pipeline in two directions.

Encode
Input File → Split into frames → RS Encode → Pack cells → Render frames → ffmpeg H.264 → Video file
Decode
Video file → ffmpeg extract → Read cells → RS Decode → Reassemble → Original file

Why it survives re-encoding

The cell grid survives YouTube's H.264 re-encoding because each 24×24 px cell spans multiple 16×16 macroblocks — no single compression decision erases it. Guard bands absorb edge artifacts, coarse gray levels tolerate luminance drift, and Reed-Solomon corrects the few cells that do flip.

Resolution is configurable via --width / --height. Default 1920×1080 produces a 78×43 cell grid.

Quick start

Get up and running in two commands.

Install

From source or download a release.

# Build from source
$ git clone https://github.com/fabricedge/ystore-go.git
$ cd ystore-go && make build

# Or download a pre-built binary from
# https://github.com/fabricedge/ystore-go/releases

Requires ffmpeg in PATH.

Basic usage

Encode, decode, verify.

$ ystore encode --input secret.pdf --output secret.mp4
$ ystore decode --input secret.mp4 --output restored.pdf
$ diff secret.pdf restored.pdf
# (no output = files match)

Multiple files

Bundle several files into one video.

$ ystore encode --input a.pdf --input b.pdf --output bundle.mp4
$ ystore decode --input bundle.mp4 --output-dir ./extracted
# extracted/a.pdf extracted/b.pdf

Custom resolution

Smaller video, fewer cells per frame.

$ ystore encode --width 640 --height 480 --input data.txt
$ ystore decode --width 640 --height 480 --input video.mp4

Background video

Embed data over an existing video.

$ ystore encode --background drone.mp4 --input secret.txt --output blended.mp4
$ ystore decode --input blended.mp4 --output restored.txt
# Non-cell areas show drone.mp4 frames

Password protection

Encrypt data with a password.

$ ystore encode --input secret.pdf --password mypass --output private.mp4
$ ystore decode --input private.mp4 --password mypass --output restored.pdf
# Wrong password: "cipher: message authentication failed"

Configuration tuning

Key parameters that affect capacity, robustness, and file size.

ParameterEffectRecommendation
--width / --height More pixels → more cells → more data per frame 1920×1080 for maximum capacity
--cell-size Larger = more robust against compression, fewer cells 24 (default) for video platforms
--bits-per-cell Higher = more data per cell, less robust 2 default; 1 for extreme robustness; 3–4 for experiments
--crf Lower = better quality, larger file 18 default; 23 for smaller files
